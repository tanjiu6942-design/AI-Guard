# GuardFilter

Build: `node scripts/build-guard-filter.mjs` (.NET SDK 8, Windows x64). Output: `vendor/guard-filter/aiguard-guard-filter.exe`, self-contained single file.

CLI stdout is JSON; errors use stderr JSON and nonzero exit. `status` is read only. `check` verifies elevation, a readable BFE engine, existing BFE automatic-start configuration, and consistency without adding filters. `lock --allow-app <absolute existing .exe>` and `unlock` require an elevated caller; the helper never elevates itself. See [offline recovery](EMERGENCY-UNLOCK.md).

Before starting the protected kernel, the elevated worker must call `stage-kernel --source <absolute existing .exe>`. It hashes the source through a read-only, non-write-sharing handle and copies it to the machine Known Folder `ProgramData/AI Guard/protected-kernel/<sha256>/mihomo.exe`, verifies the copied SHA256, and commits by an atomic rename. Only SYSTEM and Builtin Administrators receive access; the owner is Administrators and ACL inheritance is disabled on each private directory and file. Security is applied at object creation, without an initial world-readable interval. An existing directory with an untrusted owner/ACL is rejected without taking ownership. No broad ProgramData or drive-root ACL is changed. Reparse points, device/UNC/ADS paths, ambiguous path components and hard-linked source/destination files are rejected; ancestor handles disallow deletion while operating. `stage-kernel` preserves current WFP lock status and returns `kernelPath`/`sha256`. JavaScript `stageKernel(sourcePath)` returns the protected absolute path.

`lock` accepts only this hash-addressed protected image and independently verifies ancestor/file ACLs, ownership, no reparse points, and matching SHA256 before adding any WFP filters. It refuses ordinary readable application paths. This prevents a normal token from starting another instance of the excepted image; it does not establish a boundary against administrators. The probe inbound must also enforce authorization: a separate localhost port alone would allow any ordinary local application to use the excepted kernel as an open proxy.

`prepare-runtime --kernel <protected.exe>` creates an equally protected `runtime-<32 random hex digits>` beside the staged image and returns `runtimeDir`. `write-config --runtime <private runtime directory> --name <desktop-*.yaml>` reads UTF-8 YAML exclusively from stdin (maximum 16 MiB), creates an owner-Administrators file with its protected DACL in a random private temporary name, then atomically renames it without overwriting. Allowed names match `desktop-[A-Za-z0-9_-]{1,80}.yaml`; each config update must use a fresh name. This avoids both command-line secret disclosure and the implicit WRITE_DAC granted to an ordinary user who owns a file. JavaScript `prepareRuntime(kernelPath)` and `writeConfig(runtimeDir,name,content)` return absolute paths. All three setup commands return the original WFP status without locking or unlocking anything.

Four persistent blocking filters cover ALE_AUTH_CONNECT and ALE_AUTH_RECV_ACCEPT, each for IPv4 and IPv6. All use `(ALE_APP_ID != exact kernel app ID) AND (FLAGS none-set IS_LOOPBACK)`; app ID comes from `FwpmGetAppIdFromFileName0`, not a user-supplied string converted directly to a blob. An ordinary firewall allow rule cannot override a broad deny. The exception means the caller must reject ordinary business traffic inside the kernel and reserve a distinct controlled probe inbound while locked.

All four filter changes occur in one WFP transaction. Only deterministic IDs and matching ownership data are removed. Status validates enabled/persistent filters, conditions, layers, provider, sublayer and equal exception blobs. No filters returns `locked:false,complete:true`; a partial/invalid set returns `locked:true,complete:false,errors:[...]`. Callers must not display a complete machine lock unless both `locked` and `complete` are true. WFP access failures throw rather than returning unlocked. Lock repairs owned partial filters transactionally; unlock can remove owned malformed/disabled filters.

Provider association uses the already installed automatic-start `BFE` service so persistent filters remain enabled on BFE restart; this helper makes no service changes. It rejects a nonautomatic BFE configuration. Boot-time traffic before BFE is outside the persistence guarantee. Policy changes trigger ALE reauthorization of existing flows; actual connection teardown timing and interaction with third-party WFP callouts require a dedicated machine acceptance test. This is IP flow filtering, not a kernel anti-tamper or arbitrary-driver threat boundary.

Native declarations were checked against Windows SDK 10.0.26100.0 `shared/fwptypes.h`, `shared/fwpmtypes.h` and `um/fwpmu.h`. `--self-test` validates x64 struct sizes/offsets, ownership and safety predicates without WFP writes. `--test-isolated` writes only nonpersistent rules matching the helper's own exact app ID in a dynamic session; session close/crash removes them. No automatic test invokes `lock` on a real WFP engine.
