## 本次重大变更（校园网兼容、断流根治、DNS 隐私）

### 一、校园网死锁治理（坑 18-21）

1. **启动前置门（Preflight Gate，坑 18）**
   提权与启动内核前做裸网络预检（`desktop/preflight.mjs`），检测到 Captive Portal 时拒绝启动并提示先完成网页认证，杜绝"未认证前接管 DNS 与 WFP 导致认证页打不开"的死锁。
2. **免改网卡模式与体检器解耦（坑 19）**
   - 增加「修改物理网卡 DNS」开关（`takeoverDns: false`），校园网下禁止修改物理网卡，网卡保持 DHCP 下发状态。
   - `desktop/health.mjs` 体检器在免改网卡模式下直接判 DNS 项为 `ok`，消除自相矛盾误断流。
   - 增加 `buildCleanupResidualDnsScript`，退出与启动时清理 `198.18.0.2` 残留。
3. **物理出口网卡精准绑定（坑 20）**
   动态探测默认物理出口网卡并注入 `interface-name: WLAN`，关闭易失效的 `auto-detect-interface`，消除多网卡下出口被识别为 `<invalid>` 导致的全链路超时。
   **实证**：修复前日志有 789,580 条 `<invalid>` 报错，最后一条在 06:30；修复后 13:00 起归零。
4. **离线节点缓存预注入（坑 21）**
   内核启动前把 AppData 的 `airport.yaml` 注入私有沙箱目录，校园网阻断订阅拉取时仍可用 46 个本地节点建立前置隧道。

### 二、反复误断流根治（坑 22-23）

5. **国内 DoH 走 DIRECT（坑 22）**
   `doh.pub` / `dns.alidns.com` / `doh.360.cn` 从住宅组剥离为 `DIRECT`，避免国内高频解析冲垮跨境 SOCKS5 隧道。
6. **探针超时放宽到 25s（坑 23）**
   压测实测：住宅链路 16 并发全部成功，但每个耗时 10.1 秒。原 12s/10s 超时把"排队"误判成"断开"，报出 `socket disconnected before secure TLS connection was established`。
7. **前置组不再抖动（坑 23）**
   撤回前置组对「普通代理」（url-test 自动切换）的依赖。前置节点一换，住宅 `dialer-proxy` 重建，在途 TLS 握手被掐断。
8. **自测自适应降频（坑 23）**
   健康时 full 60s→180s、exit 15s→45s，异常时回到 60s/15s。full 检测含一条 30s 长连接，固定 60s 一次等于跨境通道一半时间被自测占用。
9. **出口探针并发首探 + 串行补探（坑 23）**
   三个探针原本并发打进同一条住宅隧道，互相抢通道后一起超时。改为首轮并发、失败者串行补探一次。

### 三、规则与 DNS 隐私（坑 24-25）

10. **precise 模式补上 Cloudflare 兜底（坑 25）**
    `a.nel.cloudflare.com` 在 precise 下落到 `MATCH` 走机场 IP，重现立项时的原始 bug（ChatGPT 界面无限重连）。现 strict + precise 均启用 `cloudflare.com` / `cloudflare-dns.com` 兜底。
    **注意**：原有的测试 `it("精确模式不含 cloudflare 兜底规则")` 曾把这个 bug 断言成正确行为，已同步修正。
11. **国内域名改用加密 DoH（坑 24）**
    由 `system#DIRECT` 改为 `["https://223.5.5.5/dns-query", "https://doh.pub/dns-query"]`。
    理由：`system#DIRECT` 把国内域名查询明文交给本地 ISP 递归服务器，泄漏测试直接显示"本地运营商 DNS"（校园网=中国移动、热点=中国联通 AS4837，跟着网络走）。改用 DoH 后 ISP 只能看到加密流量。
    **AI 防封不受影响**：AI 域名（`chatgpt.com`/`claude.ai`/`anthropic.com`/`gemini.google.com`）全部命中 `nameserver-policy` → `https://1.1.1.1/dns-query#AI Guard 专用`，与国内策略完全隔离。

### 四、界面与自动化

12. **界面版本号动态绑定**：`gui/src/App.tsx` 版本角标改为读取 `package.json`。

## 未验证项

- **`PROCESS-NAME` 规则从未实测命中**：配置齐全（`find-process-mode: strict` + 5 条规则），但日志中 1385 条 Claude/codex 相关连接全部是 `match DomainSuffix`，零条 `ProcessName`。判断是当时访问 Claude 的是浏览器（`chrome.exe`/`msedge.exe`），桌面客户端未运行，故规则未被触发。**这不是 bug，但也未被验证过。**
- **真实门户网络下的前置门拦截路径**：判定逻辑与提示文案由 12 个单测覆盖，但未在真实校园网门户环境跑过「未认证→拒绝启动」这条路径。
- **未开启 TUN 做完整实机验证**；本次验收未主动触发整机断流，未改动当前用户节点或系统时区。

## 已知边界（物理约束，非实现缺陷）

- **泄漏测试仍会显示"中国 DNS"**：只要用国内解析器就必然如此。想彻底消失只能把国内域名也送去住宅链路，但那会让中国 CDN 按美国住宅 IP 返回海外节点，国内站点明显变慢，并加重跨境隧道负载（坑 22/23 的成因）。当前选择是「隐去 ISP 视角」而非「完全隐身」。
- **认证过期时保持 fail-closed 断流**：校园网会话过期后 AI Guard 仍维持断流，需先退出软件完成认证。这是刻意选择，换取「保护永不静默消失」。
- **住宅隧道吞吐上限**：16 并发排队 10 秒是硬指标。并发极高时仍可能偶发 `unknown`，区别是现在会先进入 `suspect` 观察一轮，不再立刻断流。

## 安装与使用

1. 连上校园网 Wi-Fi 后，**先在浏览器完成学号密码认证**。
2. 打开 AI Guard，确认「连接配置」中**「修改物理网卡 DNS」处于关闭状态**。
3. 点击「启动内核」，正常使用。
4. 退出时用托盘「退出程序」→ 选 **「退出保护并退出」**。

> 构建安装包需 `npm run desktop:dist`，但该命令要从 GitHub 下载 Electron 二进制。当前网络下会 `ETIMEDOUT`，可先配好代理或手动放置缓存。
