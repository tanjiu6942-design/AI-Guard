# AI Guard 0.3.2 验证记录

交付 `release/AI-Guard-Setup-0.3.2-x64.exe` 与 `AI Guard/resources/app.asar`（产物不入库，已在 `.gitignore` 中）。

## 本次重大变更（校园网兼容与断流根治）

针对校园网（AYXY）环境下的四大死锁与断流问题完成系统性治理：

1. **启动前置门（Preflight Gate，坑 18）**：
   在提权与启动内核前做裸网络预检（`desktop/preflight.mjs`），明确检测到 Captive Portal 时坚决拒绝启动并提示用户先完成网页认证，杜绝“未认证前接管 DNS 与 WFP 导致认证页彻底打不开”的死锁。
2. **校园网免改网卡模式与体检器解耦（坑 19）**：
   - 连接配置中增加「修改物理网卡 DNS」开关（`takeoverDns: false`），校园网环境下彻底禁止修改物理网卡，网卡保持正统的 DHCP 下发状态，消除被学校网关检测到 DNS 偏离而断网的风险。
   - 同步修复 `desktop/health.mjs` 体检器，免改网卡时直接通过 DNS 项（`ok`），消除体检器自相矛盾误触发断流的缺陷。
   - 增加 `buildCleanupResidualDnsScript`，退出与启动时自动清理物理网卡上的 `198.18.0.2` 残留。
3. **物理出口网卡精准绑定（坑 20）**：
   通过 Windows 底层路由表动态探测默认物理出口网卡（`WLAN`），并在内核配置中注入 **`interface-name: WLAN`**，关闭易失效的 `auto-detect-interface`，彻底消除多网卡环境下内核将出口识别为 `<invalid>` 导致所有外网连接超时的 Bug。
4. **离线节点缓存预注入（坑 21）**：
   内核启动前自动将 AppData 中的离线机场节点缓存（`airport.yaml`）注入私有沙箱目录，即使校园网阻断订阅拉取，也能直接调用本地 46 个节点建立前置隧道，住宅出口握手从超时恢复至 2 秒直通。
5. **界面版本号动态绑定**：
   前端 `gui/src/App.tsx` 版本角标由静态硬编码改为动态读取 `package.json`，消除版本号漂移。

## 校园网使用建议

1. 连上校园网 Wi-Fi 后，**先在浏览器中完成学号密码认证**。
2. 打开 AI Guard，确认「连接配置」中**“修改物理网卡 DNS”处于关闭状态**。
3. 点击「启动内核」，正常使用。
