# AI Guard Windows 桌面版

用户于 2026-11-03 在聊天中确认 Electron 方案并授权开始实现。本文件记录该决定，不增加审批步骤。当前目录不是 Git 仓库，在原目录实现，不初始化仓库。

## 产品与范围

Windows 10/11 x64 独立应用，内置 Electron 运行时、编译后的 core、规则、mihomo 与 geodata。不依赖浏览器、9123 HTTP 控制面板或系统 Node.js。沿用现有 %APPDATA%/aiguard/settings.json；不把个人订阅、密码或运行日志放进安装包。

## 窗口与交互

沿用现有深色变量、Segoe UI / 微软雅黑和原生窗口标题栏。概览以连接状态为主角、启停为主动作；配置以连接参数为主角、保存为主动作；体检以六项结果为主角、运行体检为主动作；日志支持规则扫描。左侧导航保持稳定，正文独立滚动，最小窗口 820×620，初始 1080×780。动作反馈、导航指示移动和首次内容淡入采用短 CSS 动画，支持减少动态效果。

关闭窗口隐藏到托盘，托盘提供显示、停止内核、退出；退出等待清理完成。单实例避免争抢配置和端口。失败提示保留输入，不把错误渲染成成功状态。

## 进程与数据流

渲染器只加载安装包内资源，开启 sandbox/contextIsolation，关闭 Node 集成，经受限 preload API 和经来源验证的 IPC 访问 DesktopService。

普通权限窗口管理设置、日志、模式和体检。启动内核时拉起同一个 Electron 可执行文件的无窗口 worker 模式；仅 TUN worker 经 UAC 提权。通过随机命名管道传递白名单命令和状态，不启动本地 HTTP UI 服务。

worker 只拥有自己创建的 mihomo 子进程。校验配置、等待控制接口就绪后才接管 DNS；停止时等待内核退出后恢复 DNS。管道断开（包括桌面进程被强杀）时 worker 执行相同清理。独立 desktop DNS 备份避免覆盖旧 CLI 备份；残留备份在下一次启动内核时恢复。无法恢复时保留备份并报告错误，不宣称已完成。

## 功能

三种模式及热重载；订阅、住宅 SOCKS5、TUN、端口、内核路径配置；六项真实体检；日志及补丁建议。默认不自动启动内核、不自动修改系统代理或网络。配置写入先校验；运行时禁止修改需重启的连接参数。实际出口通过当前代理端口探测，停止时不探测网络。

## 打包与验收

Electron Builder NSIS 安装包和 win-unpacked 目录。构建先编译 core 和 React，再明确暂存 mihomo/geodata 与许可证，不打包个人配置。自动测试覆盖配置验证、进程所有权、启动失败清理、父进程断连清理、热重载回滚；实际 Electron smoke 覆盖 IPC、导航、配置读写、窗口与托盘生命周期。真实 TUN/DNS 驱动操作单独标明验收范围，不能用模拟测试代替实机验证。
