# 实时监测与异常自动断流设计

状态：实施中。用户已确认实时检测、异常提示及整机外网断流，保留本地界面，手动复检通过后恢复；检测周期和模块划分采用本设计的工程默认值。

## 目标与方案

把现有一次性体检扩展成后台持续监测。出现异常时提示用户并锁定整机外网，窗口最小化或隐藏到托盘时仍运行。

可选实现路径：

1. 停止 mihomo：实现简单，但 TUN 消失后应用可能恢复直连，无法满足断流目标。
2. 只把 mihomo 的业务规则切为 REJECT：能阻断已接管流量，但 DNS、IPv6 或其他代理绕过 TUN 时覆盖不足。
3. **推荐：Windows 网络层阻断与内核拒绝规则配合。** Windows 层同时处理 IPv4/IPv6；内核拒绝业务请求、关闭已有代理连接，仅保留受控复检通道。实现和验证工作较多，但符合用户确认的范围。

## 检测和触发

- 启动保护必须使用 TUN，并取得管理员权限。先校验系统阻断能力及内核配置；保护准备失败时不显示“受保护”。
- 启动时完整检查一次；首次检查未通过时进入锁定，不开放业务流量。
- 每 5 秒检查本机关键状态：内核、控制连接、TUN、DNS/IPv6 配置和代理冲突。任何一轮只运行一个实例，防止任务重叠。
- 每 15 秒执行出口连通性和一致性检查。目标选用当前所有分流模式均覆盖的无账号公共端点；出口基准取经验证的实际住宅出口，不把 SOCKS5 网关地址当作出口。
- 每 60 秒执行六项完整体检，其中长连接测试本身约需 30 秒。切换网络、休眠唤醒或修改模式后立即补查。
- 发现明确出口改变、泄漏或 TUN 接管失效时立即进入锁定流程。单次超时、采集失败或其他非正常结果先提示，5 秒后复查；复查仍未通过则锁定。所有检查必须有截止时间，挂起不能被算作正常。
- 这是一套周期监测，不称为毫秒级无间隙防护。界面显示每个检查的时间、正在复核的异常和最近一次完整体检时间。

## 断流与提示

- 权限 worker 承担监测和锁定执行，渲染页面只展示状态，隐藏窗口不影响监测。
- 异常锁定时，Windows 过滤规则阻断普通应用外部连接，覆盖 IPv4 与 IPv6；本机回环和管理 IPC 保留。
- 同时拒绝 mihomo 的普通业务请求并关闭既有代理连接，防止应用通过本地代理继续联网。单独的复检入口只供监测使用，不混用业务代理端口。
- 仅为受控复检保留所需的内核/探测能力，复检期间不开放普通应用。阻断规则不能只按当前网卡名称绑定，否则换网卡会失去保护。
- 界面显示红色“已断流”、触发原因、触发时间及各项结果；托盘同步显示异常状态，并尝试发送 Windows 通知。系统通知被关闭或不可用不影响断流和本地告警。
- 若系统阻断执行失败，明确显示“断流失败”，拒绝内核业务流量并继续尝试系统阻断，不能显示“整机已断流”。
- 系统规则使用本软件专属标识，只清理本软件规则。规则需可持久保存，异常锁定不能因界面退出或重开自动解除。

## 恢复与退出

- 不自动恢复联网。用户点击“复检并恢复”后，在锁定状态下执行完整体检；全部通过后才解除业务拒绝和系统阻断，并继续后台监测。
- 复检失败、超时或无法判断均维持锁定，更新原因。
- 普通关闭窗口只隐藏到托盘。锁定时点击退出保留断流，并在下次打开时显示锁定状态。
- 单独提供“退出保护并恢复普通网络”应急入口，明确说明将停止安全保护，由用户再次确认后移除本软件阻断规则、停止内核并恢复 DNS。该入口不是“复检通过”，不能展示保护成功。
- 给出离线可用的应急解除工具或操作说明，保证软件损坏时仍可由用户主动恢复网络。

## 代码边界

- 新增独立监测状态机，负责周期、重试、检查过期、锁定和手动恢复，便于使用可控时钟测试。
- 新增 Windows 过滤适配器，封装原生网络过滤能力、专属规则查询/安装/删除、执行结果校验及权限错误。
- 权限 worker 集成状态机、规则锁定和受控复检；管理管道提供只读保护状态、手动复检恢复和明确退出保护操作。
- DesktopService、preload 和 TypeScript IPC 契约增加对应接口。主进程负责通知及托盘展示。
- 网络体检页展示持续监测状态和检查时间；概览页区分“正在检查”“正常保护”“异常复核”“已断流”“恢复复检”“断流失败”。
- 更新启动、退出和卸载说明，避免旧版“退出即恢复普通网络”与锁定状态冲突。

## 验证与交付

1. 用失败测试覆盖检测异常、短暂超时重试、单次运行、过期结果、锁定幂等、恢复失败保持阻断、全部通过才解锁，以及关闭窗口后继续运行。
2. 用受控内核和探测夹具验证业务连接被拒绝、既有代理连接关闭、复检通道仍可用、模式切换不能解除锁定。
3. 系统过滤规则在独立测试目标上验证 IPv4/IPv6 和已有连接处理；验证新增规则不修改其他软件规则。
4. 自动测试不对用户当前联网环境触发整机断流；正式实机断流验收须由用户在可接受断网时启动，提供本地操作和应急恢复方式。
5. 完成回归、打包自检与代码复核，交付更新安装包。当前运行的软件在更新前保持原逻辑。

## 技术依据与边界

- Windows WFP 提供按应用等条件的过滤，以及持久过滤对象；ALE 层策略改变会触发已有连接重新授权。[WFP 条件类型](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/filtering-condition-data-types)、[过滤对象与持久性](https://learn.microsoft.com/en-us/windows/win32/api/fwpmtypes/ns-fwpmtypes-fwpm_filter0)、[ALE 重新授权](https://learn.microsoft.com/en-us/windows/win32/fwp/ale-re-authorization)。
- 普通 Windows 防火墙显式阻断规则优先于允许规则，不能假设“阻断全部再允许探测进程”就能工作。实现受控复检时必须验证例外条件和业务拒绝配合。[规则优先级](https://learn.microsoft.com/en-za/windows/security/operating-system-security/network-security/windows-firewall/rules)。
- 软件探测不能证明所有网站、所有 STUN 端口和所有浏览器行为均无泄漏。进程或系统崩溃到监测代码来不及执行的情形，不宣称为已验证的无间隙防护；持久锁定则必须在执行成功后保持。
